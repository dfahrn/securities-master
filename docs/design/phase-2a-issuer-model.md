# Phase 2a — Issuer Model and Exchange Listings

**Date:** 2026-08-19
**Status:** Approved for planning
**Builds on:** `securities-master.md` (project spec), Phases 0–1 as merged at
`44aa4b3`

## 1. Purpose

Phase 1 shipped an identity layer that could not represent a company with more
than one class of stock. Measured on real data, that cost 2,401 of 10,396
tickers — 23% of the universe, including `GOOG`, `BRK-A`, and every fund trust
with multiple series.

The cause was a modeling error, not a bug: **CIK identifies an issuer, not a
security.** Alphabet is one SEC filer with two securities. Because CIK was
stored in `core.security_identifier` under an exclusion constraint that forbids
one identifier mapping to two securities on overlapping dates, the schema made
the correct representation impossible, and the normalizer's create-or-skip
behaviour was the only shape it permitted.

Phase 2a introduces `core.issuer`, moves CIK onto it, and re-derives `core` so
that one row exists per (CIK, ticker) rather than per CIK. It also populates
`core.security_listing`, which has been defined and empty since Phase 1.

## 2. Scope

**In scope:** the `issuer` table; `security.issuer_id`; removal of `cik` from
`security_identifier`; a switch to SEC's `company_tickers_exchange.json`; a
per-filer pass over the SEC submissions API; population of `security_listing`;
partial `security_type` classification; full re-derivation of `core` from
`landing`.

**Out of scope:** daily bars, trading calendars, and the yfinance adapter (Phase
2b); corporate actions and price adjustment (Phase 3); delisting history and
identifier backfill (Phase 4).

## 3. Findings that shaped this design

These were measured during design, not assumed. They are recorded because
several contradict what was believed when Phase 2 was first sketched.

**`company_tickers_exchange.json`** has fields `['cik', 'name', 'ticker',
'exchange']` and 10,398 rows over 7,998 distinct CIKs.

| exchange | rows |
|---|---|
| Nasdaq | 4,347 |
| NYSE | 3,312 |
| OTC | 2,514 |
| *(null)* | 197 |
| CBOE | 28 |

**`entityType` does not classify instrument type.** Observed: Apple
`operating`/SIC 3571; SPDR S&P 500 ETF `other`/SIC empty; Alphabet
`operating`/SIC 7370; Alibaba ADR `other`/SIC 7389. The value `other` covers
both the ETF and the ADR, so it separates operating companies from everything
else but cannot distinguish a fund from a foreign issuer.

**Submissions payloads average 115 KB** (0.94 GB across 7,998 filers);
entity-only fields average 0.32 KB (2.6 MB). The full payload is landed anyway:
~1 GB is affordable, and `filings.recent` — the sub-document a slimming step
would discard — is exactly where Phase 4 finds Form 25 delisting notices.

**Submissions and the ticker file disagree.** Alphabet's submissions lists
`GOOGL, GOOG, GOOGM, GOOGN`; the ticker file lists two. Two SEC endpoints
contradicting each other is a genuine reconciliation case available at no cost.

## 4. Governing decisions

**D1 — CIK gets no date range.** It is SEC-assigned, permanent, and never
recycled. `issuer.cik` is a plain `UNIQUE` column. The asymmetry with tickers is
correct: a ticker is a lease that exchanges reclaim and reissue, so
`ticker → security` is a function only when a date is supplied; `CIK → issuer`
is a function for all time.

**D2 — SEC's assertions are stored as facts, our inferences are not.**
`entity_type`, `sic_code`, and `sic_description` are persisted verbatim on
`issuer`. `security_type` is derived from them and may be revised later without
re-fetching.

**D3 — partial classification beats confident mislabelling.** `operating` maps
to `common_stock`; everything else maps to a new `unknown`. Today every security
including SPY is labelled `common_stock`, which is false. `unknown` is true.

**D4 — OTC and null-exchange rows are excluded and counted.** They are mostly
illiquid shells and foreign secondary lines that would pollute a research
universe. Excluding them is a reported gap, not a silent one.

**D5 — everything lands before anything truncates.** The destructive migration
runs only after both payloads are safely in `landing`.

**D6 — `core` is re-derived, not migrated in place.** Nothing depends on
`security_id` yet; after Phase 2b lands bars, nothing like this is free again.

## 5. Schema

### 5.1 New

```
core.issuer
  issuer_id        bigint GENERATED BY DEFAULT AS IDENTITY  PK
  cik              text NOT NULL UNIQUE      -- 10-digit zero-padded
  name             text NOT NULL
  entity_type      text NULL                 -- SEC's value verbatim
  sic_code         text NULL
  sic_description  text NULL
```

No temporal columns, per D1.

### 5.2 Changed

```
core.security
  + issuer_id      bigint NOT NULL REFERENCES core.issuer(issuer_id)
  security_type    CHECK extended to ('common_stock', 'etf', 'adr', 'unknown')
```

`IDENTIFIER_TYPES` becomes `('ticker', 'cusip', 'isin', 'figi')`; the
identifier-type CHECK drops `'cik'`. The GiST exclusion constraint on
`security_identifier` is unchanged and continues to guard tickers.

### 5.3 Populated for the first time

`core.security_listing` receives one row per security, mapped from the file's
exchange string:

| file value | MIC |
|---|---|
| `Nasdaq` | `XNAS` |
| `NYSE` | `XNYS` |
| `CBOE` | `BATS` (Cboe BZX Exchange; the file's generic `CBOE` gives no finer venue) |
| `OTC`, null | *(row excluded, counted)* |

`valid_from` is the landing row's `fetched_at` date; `valid_to` is NULL;
`delisting_reason` is NULL. Migration `0008` adds the `BATS` exchange row and
removes the `ARCX` seed, which no data ever referenced.

### 5.4 Landing

```
landing.edgar_company_tickers_exchange
  landing_id, fetched_at, payload_hash UNIQUE, payload JSONB

landing.edgar_submissions
  landing_id, cik, fetched_at, payload_hash, payload JSONB
  UNIQUE (cik, payload_hash)
```

The submissions table is keyed per filer because 7,998 fetches is a
long-running job that must survive interruption.

## 6. Ingestion

Two new adapter methods on `EdgarAdapter`, matching the existing shape:

```python
fetch_company_tickers_exchange_payload() -> dict
fetch_submissions_payload(cik: str) -> dict
```

**The fetch loop** (reused by Phase 5, so it is built properly here):

- rate limited to **8 requests/second** against SEC's stated limit of 10 —
  headroom, not optimism. ~17 minutes for 7,998 filers.
- retries with exponential backoff on 429 and 5xx, capped attempts
- **resumable**, and the skip is scoped to the current run, never to the table.
  A skip rule of "CIK already exists in `landing`" makes the first run correct
  and every later run a no-op, permanently hiding name changes, new tickers,
  and Form 25 filings. This must be pinned by a test that runs the loop twice.
- a CIK exhausting its retries is **recorded and counted, never fatal**. The run
  completes with a coverage number rather than losing 6,000 successful fetches
  to one failure.

Normalization reads the exchange file only. The submissions `tickers` array is
landed and compared, never used as a source, so the disagreement is measurable.

## 7. Normalization

Per row of `company_tickers_exchange.json`:

1. Skip and count rows whose exchange is `OTC` or null (D4).
2. Upsert `issuer` by CIK, taking `name` from the file and `entity_type` /
   `sic_code` / `sic_description` from that CIK's landed submissions payload.
   When no submissions payload exists for that CIK — the fetch failed and was
   counted per §6 — the three SEC-derived columns are left NULL and the
   security's `security_type` becomes `unknown`. A missing fact is recorded as
   missing, never guessed from the name.
3. Insert one `security` per row, linked to the issuer.
4. Insert its `ticker` identifier, `valid_from = fetched_at.date()`.
5. Insert its `security_listing` row with the mapped MIC.

`security_type` is `common_stock` when `entity_type == 'operating'`, otherwise
`unknown` (D3).

An `issuer` row is created only for a CIK with at least one included security.
A filer appearing solely on excluded OTC or null-exchange rows produces no
issuer, so the issuer count is strictly below the file's 7,998 distinct CIKs;
the exact figure is whatever the run reports and is not predicted here.

**Expected outcome:** ~7,687 securities, fewer than 7,998 issuers, with 2,711
rows excluded and reported. The security count falls from Phase 1's 7,995 while the
model becomes more correct — share classes are now represented and OTC shells
are not. That direction of movement must be stated in the run output, not
discovered later.

`NormalizeResult` gains fields for the new counters; existing fields keep their
meaning.

## 8. Client

```python
sm.issuer_for(conn, security_id) -> Issuer
```

Returns the issuer owning a security, so research code can ask what else a
filer issues. `resolve()` and `identifiers_for()` are unchanged in signature;
`identifiers_for` no longer returns a `cik` entry, because CIK is no longer a
security identifier.

## 9. Migration

Migration `0008`, in order:

1. `TRUNCATE core.security_identifier, core.security_listing, core.security
   RESTART IDENTITY CASCADE`
2. `CREATE TABLE core.issuer`
3. `ALTER TABLE core.security ADD COLUMN issuer_id bigint NOT NULL REFERENCES
   core.issuer(issuer_id)`
4. Replace the `security_type` and identifier-type CHECK constraints
5. Insert the `BATS` exchange row; delete the `ARCX` row

Step 3 may declare `NOT NULL` without a default only because step 1 emptied the
table. The migration is destructive, and that is acceptable for exactly one
reason: `core` is fully derivable from `landing` (project principle P4), a
property Phase 1 pinned with a replay test. The downgrade is lossy and must say
so in a comment.

## 10. Testing

- `issuer.cik` rejects a duplicate
- one issuer with two securities — `GOOGL` and `GOOG` under CIK 1652044, the
  case that motivated this phase
- OTC, null, and CBOE rows: the right ones excluded, the excluded ones counted
- `operating → common_stock`; `other → unknown`
- `security_listing` carries the correct MIC for each exchange string
- the replay test from Phase 1, extended: a rebuild still reproduces identical
  dates under the new schema
- **the fetch loop run twice**, asserting the second run refetches rather than
  skipping wholesale
- a CIK whose fetch fails is counted and does not abort the run
- cross-source ticker disagreement is measured
- every comparison operator introduced in this phase gets one test that fails if
  it is flipped (the rule adopted after Phase 1's fourth boundary-testing hole)

`core` before the submissions data is safely landed would leave an empty
database and a 17-minute recovery.
